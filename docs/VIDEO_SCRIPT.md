# Сценарий видео-демо CLAIR PRO (~6 минут)

Формат: запись экрана (Win+G или OBS), микрофон включён, окно браузера ~1440×900, тёмная тема.
Перед записью: закрыть лишние вкладки, увеличить масштаб браузера до 110-125 %, консоль launcher — слева, браузер — справа.

---

### 0:00–0:25 — Интро
Экран: README.md (прокрутка до схемы архитектуры).
Реплика: «Это CLAIR PRO — единый продукт поверх трёх независимых сервисов: неизменяемого ядра сжатия CLAIR Base, шлюза Gateway с кэшем промптов и визуального дашборда. Сейчас запустим всё одной командой и пройдём по приборной панели.»

### 0:25–1:00 — Запуск одной командой
Экран: консоль.
1. `type README.md | more` → показать схему (5 с, пролистать).
2. `clair-pro.bat`
3. Показать построчно: `[clair-base] готов… [gateway] готов… [dashboard] готов…`, браузер открылся сам.
Реплика: «Одна команда. Launcher нашёл CLAIR Base, поднял шлюз и дашборд, дождался health-проверок и открыл браузер. Если сервис уже запущен — он переиспользуется, второй не стартует.»

### 1:00–2:00 — Первый запрос и метрики
Экран: дашборд.
1. Показать KPI-карточки (10 запросов, экономия, коэффициент, кэш, задержка).
2. Прокрутить до «Тестовый запрос через Gateway». Ничего не меняя, нажать **Отправить ▸**.
3. Показать ответ LLM и чипы: «сэкономлено 9 ток.» «коэф. ×1.53» «кэш: MISS» «49 мс».
4. Обратить внимание: новая строка появилась в таблице сама (~1 с), без F5 — это SSE.
Реплика: «Запрос идёт с дашборда в Gateway, тот сжимает промпт через CLAIR Base и только потом — в LLM. Оба сервиса дописали свои JSONL-логи, дашборд подхватил их в реальном времени.»

### 2:00–2:40 — Кэш
1. Нажать **Отправить ▸** ещё раз (тот же текст).
2. Чип теперь «кэш: HIT».
3. В таблице — новая строка с HIT; задержка меньше.
Реплика: «Повторный промпт не дёргает CLAIR Base — срабатывает LRU-кэш шлюза. Экономия та же, задержка ниже. MISS, HIT, частичные попадания и bypass — всё видно на донате.»

### 2:40–3:40 — Графики и фильтры
1. Прокрутить к графикам: экономия по часам, сессии, кэш-донат, latency.
2. В фильтрах таблицы: выбрать «кэш: HIT» → таблица сузилась; поиск «gpt-4o» → только эти строки; «× сброс».
3. Экспорт: нажать **CSV** (файл в загрузках), открыть — заголовок и строки в Excel.
Реплика: «Все данные читаются из двух JSONL-логов — Base и Gateway, — фильтруются на сервере и экспортируются в CSV или JSON. Никаких баз данных — только файлы.»

### 3:40–4:40 — Границы: Base не тронут
Экран: консоль, разделённая.
1. `cd C:\Clair_pilot && git status` → «working tree clean».
2. `type C:\Clair_pilot\logs\clair_pilot.log.jsonl | more` → показать строки формата `session/mode/input_tokens/...`.
Реплика: «CLAIR Base — чёрный ящик: ни один файл в его каталоге не изменён. Мы вызываем только POST /compress и читаем его лог. Весь новый код живёт в clair-pro.»

### 4:40–5:30 — Отказоустойчивость и demo-режим
1. В консоли launcher: **Ctrl+C** → показать аккуратное выключение трёх сервисов.
2. `clair-pro.bat --demo` → показать «Режим: DEMO», mock Base + mock LLM.
3. В UI отправить запрос — цикл работает оффлайн.
Реплика: «Ctrl+C гасит все процессы без зомби. А флаг --demo поднимает моки Base и LLM — продукт работает из коробки, без ключей и интернета.»

### 5:30–6:00 — Финал
Экран: README (раздел «Что умеет Dashboard»).
Реплика: «Итого: оркестрация одной командой, живая приборная панель с real-time, экспорт, соблюдение границ — и полное покрытие тестами: 14 API-тестов и 6 сквозных. CLAIR PRO готов к использованию.»

---

### Технические заметки
- Разрешение 1920×1080, 30 fps, MP4. Не обрезать консоль — текст должен читаться.
- Если SSE не сработал мгновенно — подождать 5 с (автообновление), это тоже упомянуть.
- Перед дублем 3:40 проверить, что в таблице есть HIT-записи (шаг 2:00 обязателен до этого).
- Альтернатива ручной записи: `npm run smoke` в отдельной консоли на 0:25 — зелёный вывод смоука можно показать вместо ручных curl.
